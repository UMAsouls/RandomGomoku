# AlphaZero並列処理版

このディレクトリには、CPUコア数に応じて自己対戦を並列実行するAlphaZeroの実装が含まれています。

## 主な特徴

- **並列自己対戦**: CPUコア数に応じて複数のプロセスで同時に自己対戦を実行
- **効率的なデータ収集**: 並列処理により大幅な時間短縮を実現
- **従来版との互換性**: 既存のモデルとの互換性を保持
- **動的負荷分散**: 利用可能なCPUコア数に応じて自動的にワーカー数を調整

## ファイル構成

- `alpha_gomoku_parallel.py`: 並列処理版AlphaZeroのメイン実装
- `run_parallel_training.py`: 並列トレーニングの実行スクリプト
- `benchmark_parallel.py`: 並列版と従来版の性能比較ベンチマーク
- `README_parallel.md`: このファイル

## 使用方法

### 1. 基本的な実行

```bash
python run_parallel_training.py
```

### 2. パラメータを指定した実行

```bash
python run_parallel_training.py --workers 4 --games-per-batch 8 --total-batches 1000
```

### 3. 利用可能なオプション

- `--workers`: 並列ワーカー数（デフォルト: CPU数-1）
- `--games-per-batch`: バッチあたりのゲーム数（デフォルト: 4）
- `--total-batches`: 総バッチ数（デフォルト: 5000）
- `--playout`: MCTSプレイアウト数（デフォルト: 400）
- `--check-freq`: モデル評価の頻度（デフォルト: 100）

### 4. 性能ベンチマーク

並列版と従来版の性能を比較：

```bash
python benchmark_parallel.py
```

## 技術的な詳細

### 並列処理の実装

1. **ProcessPoolExecutor**: 複数のプロセスで自己対戦を並列実行
2. **モデル状態の共有**: `state_dict`を使用してモデルの重みを各プロセスに渡す
3. **データ収集**: 各プロセスが独立してゲームデータを収集し、結果をマージ
4. **ThreadPoolExecutor**: データ拡張処理を並列化

### 最適化のポイント

- **メモリ効率**: 各プロセスが独立したモデルインスタンスを持つ
- **CPU使用率**: 利用可能なCPUコア数に応じて動的にワーカー数を調整
- **エラーハンドリング**: 個別のプロセスでエラーが発生しても全体の処理を継続

## 性能の期待値

- **4コアCPU**: 約3-4倍の高速化
- **8コアCPU**: 約6-7倍の高速化
- **16コアCPU**: 約12-14倍の高速化

実際の性能は、MCTSの計算量とシステムの性能に依存します。

## 注意事項

### システム要件

- **Python 3.7+**: マルチプロセシングの`spawn`メソッドが必要
- **十分なメモリ**: 各プロセスが独立したモデルを持つため、メモリ使用量が増加
- **CPU負荷**: 全CPUコアを使用するため、システムが重くなる可能性があります

### トラブルシューティング

1. **メモリ不足**: ワーカー数を減らすか、モデルサイズを小さくする
2. **プロセス起動エラー**: `multiprocessing.set_start_method('spawn')`が正しく設定されているか確認
3. **GPU競合**: 並列処理時はCPUのみを使用することを推奨

## 従来版との比較

| 項目 | 従来版 | 並列版 |
|------|--------|--------|
| 自己対戦 | 逐次実行 | 並列実行 |

| 安定性 | 高い | 中程度 |
